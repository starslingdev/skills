- **2026-11-20** — Add OPT114 for CI jobs that keep npm audit reporting in a host `npm ci` but repeat the same advisory lookup in Docker image layers that install or prune from that same lockfile. The host install must keep audit on through its flags, environment and every repository `.npmrc` from its effective working directory (inherited `defaults.run.working-directory` included) up to the root, and must run whenever the image build runs (no `if:`, or the build's own); a `cd`, `--prefix` or expression directory, heredoc or quoted text, and a job-wide `npm config set audit` or `NPM_CONFIG_AUDIT` written to `GITHUB_ENV` withhold it. On the image side only the selected build stage and the stages it builds from count, the image must copy in the host install's lockfile, and audit settings are read in Docker order as the image sees them (`ENV`/`ARG NPM_CONFIG_AUDIT`, `npm config set audit`, a copied `.npmrc`); a build-context `.npmrc` the Dockerfile never copies does not count. The static finding recommends `--no-audit` only in those image layers, preserves the host audit and the image parity checks, and states the runner-minute effect as a saving left unsized until Docker-layer timing and 30-day job volume are measured (#427).
