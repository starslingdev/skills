# Real-repository golden reports

This maintainer-only suite records public GitHub Actions data once and replays
it offline. The independent oracle reads the normalized month-wide run and job
history without importing the report engine. Expected files contain oracle
facts plus human-reviewed report expectations. They are never generated by the
engine.

Every expected file starts as `awaiting owner sign-off`. Refreshing a recording
does not update its expectation automatically. A reviewer must compare the
recording, oracle output, and rendered report and explain any expected-file
change.

`record.py` is resumable while collecting month-wide jobs. It passes live API
responses through the existing record/replay seam, caps committed logs, and
deletes any log that trips its secret scanner. Run `oracle.py` separately to
produce reference facts, then review and copy those facts into the proposed
expected file.

Before committing, the recorder rewrites long numeric API identifiers to
stable eight-digit fixture identifiers across both response bodies and replay
filenames. The relationship between runs, jobs, workflows, and endpoints stays
intact while the public fixture follows the repository's identifier policy.

Busy repositories can exceed the Actions API's 1,000-result cap. The recorder
therefore reads the 30-day window in daily slices. For each PR commit it fetches
the job list of the workflow run that completed last, walking backward only
when that run contains bookkeeping jobs shorter than the configured cutoff.
The in-progress state is local-only and removed after a complete recording.
Committed API identifiers are rewritten consistently to short fixture IDs;
their values carry no meaning in either the oracle or the engine comparison.

Replay also exposes the normalized month through ordinary workflow-run and
job-list fixture names. It keeps the detailed live page 1, then materializes
older page-2-and-later responses with deterministic fixture IDs. This lets a
deeper sampling implementation consume the same pinned recording without a
new network capture or an engine-written expectation.
